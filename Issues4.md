- Overriding the TalonFX may not be the best choice. You have renamed the setControl to setParadoxControl. This means that the original setControl can still be called by accident by someone not paying too much attention. Overloading that function does not completely fix the problem since there are numerous setControl overloads in TalonFX and you would need to overload them all to make it safe. A better approach would be to create a standalone class that simply creates an instance of the TalonFx inside. This would allow you to pick an choose what functions you support. This would probably involve more work because you would have to implement all the TalonFX methods that you are going to need
- Going neutral might be unsafe if you were positioning an arm that has a gravitational component going to neutral would drop whatever it was holding. I am not sure whether the neutral mode keeps the brake setting. If it does it might be ok if the brake can hold the position all by itself. I am not sure this would work well with a position PID so perhaps you need a different class for that anyway.
- Your code will only protect the motor if you are using velocity. It would not work in any other modes
- In the constructor you are trying to set the motor. I suppose that if you only set it to neutral that would be ok but if someone called it with a set power it would mean that the motor would start as soon as the robot is enabled.
- Perhaps you should report the stall to the driver station or put it on elastic as a big red button?
You might look into using the StatusSignal<Current> / StatusSignal<AngularVelocity> classes instead of numerical constants for the current and speed. Not a big deal but these allow you to easily ask for unit conversions.
